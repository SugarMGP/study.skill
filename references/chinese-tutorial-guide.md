# 中文教程写作规范

> 综合参考：阮一峰、廖雪峰、JavaGuide、CS-Notes、Rust 中文社区教程、ai-agents-from-zero、极客时间等中文教程的常见写法。

本文件只规定中文课件的表达、章节组织和中文读者体验。图表、图片、代码、可保存练习块等跨语言课件格式看 `courseware-format.md`。

## 核心取向

中文教程要像一个带人的师傅：先把问题讲明白，再带学习者动手或推理，最后确认他是不是真的会了。不要写成资料汇编，也不要写成静态题库。

## 教学口吻

中文课件需要一个可感知的、自然的师傅声音。不是冷冰冰的知识百科，但也不是编造经历的表演。建立口吻的正当方式：

- **直接跟学习者说话**：用"你"，用"我们来看看"，不用"学习者""读者"等第三人称。
- **自然的长短句交替**：短句给结论，长句给解释。不追求每句一样长。
- **用源材料中的具体事实和观察说话**：例如"dd2l.ai 的作者指出，无激活函数的多层网络实际上是线性的"——这是可查证的引用，不是编造的经历。
- **承认难度但不编造共情**：可以说"这个概念确实绕""这里有两个容易混的点"，因为这是客观事实。不编造"我第一次学的时候""我踩过一个坑"——agent 没有这些经历。
- **适当的生活化表达**：允许在自然场景下使用当下通用的中文表达、成语、俗语，包括"绕晕了""这个真不怪你""先试试看""翻车了"等。一节出现 1-2 处自然表达即可，不要刻意堆梗，不能低俗，不偏离教学主线。

你是一个知识广博、说话实在的师傅——不是假装你经历过这些事情的人。

AI 写作警惕词和禁用句式见 `references/anti-ai-writing.md`。

推荐主线：

```text
问题入口 -> 人话直觉 -> 术语和边界 -> 例子/代码/案例 -> 判断标准 -> 互动练习 -> 收束
```

中文课件应当让学习者在每章结束时知道三件事：

- 这章到底解决了什么问题。
- 我现在能判断、能解释、能动手做什么。
- 哪些地方我还容易混，下一次学习从哪里接上。

## 三层递进结构

**技术主题：**

```text
第一层：基础入门（30%）-> 建立概念，跑通第一个程序
第二层：核心能力（40%）-> 深度讲解，动手实践
第三层：进阶实战（30%）-> 原理深挖，项目/面试/考试应用
```

**非技术主题：**

```text
第一层：基础入门（30%）-> 建立概念框架，理解核心问题
第二层：深层理解（40%）-> 关键理论、案例、推导
第三层：批判拓展（30%）-> 不同学派、前沿讨论、自选专题
```

## 自然章节结构

不要把课件写成固定模板。每章必须形成学习闭环，但标题和组织方式要跟主题走。

一章对应一个可折叠模块，模块根目录的 `content.md` 只写章节前言：

- 这章要解决的核心问题。
- 学习者需要具备的前置条件；缺了就指出本章会补哪一小段。
- 本章小节目录，每个小节解决什么问题；具体文件和导航规则看 `courseware-format.md`。
- 本章完成后能做出的判断、解释或操作。

真正的正文写进小节文件。小节拆分、合并和导航链接规则以 `courseware-format.md` 为准；这里强调中文写法：系统精讲和考试备考按 phase-2-generation.md 的模块结构护栏和拆分规则组织小节；每个小节必须能独立学习。

小节正文自然包含这些内容，不要求固定标题：

- 用真实问题、错误现象、工作场景或反直觉点开场。第一段不列出 2 个以上未解释的术语。
- 先用人话建立直觉，再给准确术语；首次概念介绍按 `courseware-format.md` 的规则处理，中文里要顺手解释，不要让学习者靠上下文猜。
- 用 2-5 个样本数据、不超过 10 行的代码或一个具体案例起步，再过渡到真实规模。
- 在概念旁边给判断标准：什么时候用，什么时候不用，和相似概念怎么区分。
- 如果 Phase 1 调研从课程教材、真题或权威资料中找到已知误解，放在相关知识点旁边拆解；否则不写。
- 需要学习者作答时，用 `study-*` 题块；链接、题块和导出规则看 `courseware-format.md`。
- 小节末尾可以自然收束 2-5 条要点；不要写空泛的“建议下一步”。

中文正文必须落实 `courseware-format.md` 的共享教学完整性规则。中文写法上的落点是：把资料讲成讲义，补前置、加过渡、换成人话、用小例子垫一下，再进入原材料里的术语、图、公式、代码或结论；不要写成资料汇编、关键词清单或压缩笔记。

考试备考课里，“重点清单”只能当导航，不能当正文。具体深度门禁由 `phase-2-generation.md` 负责；中文正文要把重点写成能答题的讲义，而不是把“重点掌握”四个字换个说法。

成熟中文教程通常不是“先给目录，再给定义”，而是把一个问题顺着讲完：先有问题入口，再贴近原材料给图、代码、例题、公式或表格，接着解释每一步在解决什么，最后用练习把学习者拉回来。生成课程时沿用这个结构；用户提供的课件、教材和题目如果本身讲得好，可以保留原句、原图、原表和原题，再补中文过渡、背景和易错点。

## 初学者入口要求

系统精讲不是把所有概念压进一章。面向初学者或弱前置学习者时，每个基础模块必须先搭入口，再进入术语和公式。

基础模块必须满足：

- 开头先给一个具体问题或场景，不要第一段就堆定义。
- 每个核心术语或核心概念第一次出现时，用一句人话解释它“在解决什么问题”。
- 第一个例子使用 2-5 个样本数据或日常/工程场景；不要直接使用真实模型规模、论文公式或复杂代码。
- 从例子到抽象概念之间要有过渡句，说明“这个小例子和真实系统哪里一样，哪里不一样”。
- 如果学习者画像里写着数学、语言、工具前置薄弱，要在相关小节补一个“够用前置”，只讲当前小节马上会用到的部分。
- 不要把官方链接、练习题或扩展阅读提前到概念还没讲清楚之前。

弱写法：

> 向量是有序数列，矩阵是二维数组，张量是多维数组。Transformer 输入张量形状为 `[batch, seq, hidden]`。

好写法：

> 先想一个问题：模型看到一句话时，电脑里到底放的是什么？它不是中文句子，也不是 Java 对象，最后只能是一堆数字。我们先从一句 4 个词的小句子开始看，每个词用 8 个数字表示，这样才能一步步理解 `[batch, seq, hidden]`。

## 反面教材开场（初学者的 Pain-First 适配）

面向初学者的小节，可以先展示一个一眼就能看出不对的写法或场景，再引出正确思路。这不同于 `teaching-patterns.md` 的通用"痛苦先行"模式——初学者的失败场景必须是感性可理解的（"这段代码怎么会崩？""这个数据怎么全变成 NaN 了？"），不需要技术背景才能看懂。

具体模式和结构以 `teaching-patterns.md` 模式 1（痛苦先行）和模式 5（错误驱动教学）为准；本节只规定中文初学者的入口风格。

## 代码走读的中文表达

当采用 `teaching-patterns.md` 模式 4（手把手跟踪）时，中文课件中的走读表达遵循以下规则：

- 走读结构以 `teaching-patterns.md` 模式 4 为准，这里不重新定义。
- 每一步状态变化用中文短句标注，不翻译英文变量名。
- 最终总结用中文简单句："最终的执行顺序是 part1 → part3 → Handler → part4 → part2。"

## 中文题目写法

题块类型、字段、答案展示时机和纯题目小节规则以 `courseware-format.md` 为准；这里不重写 schema。中文题目要像老师当面出题：题干说清任务、材料、限制和作答角度，别只写“请分析”“谈谈理解”。

题量不重要，重要的是每题能暴露一个具体的理解缺陷。面试题要问出判断标准，考试题要给足题面数据，代码题要有输入输出或错误现象，理论题要说明要辨析、证明、反驳还是套公式。

## 中文表达原则

### 1. 先讲人话，再给术语

先用日常语言建立直觉，再给出精确术语。

首次概念介绍按 `courseware-format.md` 执行。中文写法上，主角概念要先讲直觉和例子，配角概念给一句工作定义，只需识别的词可以括号注释。

好写法：

> 可以把 Hook 理解成一个钩子：它把 React 的状态能力钩到函数组件上，让函数组件也能记住数据。这个钩子的学名叫 `useState`。

弱写法：

> `useState` 是 React 的一个 Hook API，用于在函数组件中管理状态。

### 2. 核心概念要有抓手

当 learner_profile.analogy_preferences 或 known_languages 提供可映射的已知领域时，使用类比。类比必须说明至少一处不同。

当 learner_profile 中无可映射领域时，跳过类比，从更简单的问题逐步推导。

### 3. 判断标准要明确

不要只说“是什么”，还要说明：

- 什么时候用？
- 什么时候不用？
- 和相似概念怎么选？
- 看到什么现象，说明理解可能错了？

能用对比表格就用表格；表格讲不清时，用两个具体场景对比。

### 4. 示例和练习要贴近中文读者

**技术主题：**

- 代码注释使用自然中文，不写英文注释的直译版。
- 只有学习者需要亲自运行代码时，才展示必要安装命令、运行命令和预期输出；运行时说明的边界按 `courseware-format.md`。
- 需要依赖版本时，只写会影响学习或运行结果的版本要求。
- agent 没有实际运行代码时，在聊天交付说明里讲清楚，不写进学生课件正文。
- SQL 建表、约束、查询、公式推导、接口调用这类需要动手或作答的内容，按 `courseware-format.md` 的完整示范规则写；中文解释要逐句讲清“这一步在解决什么问题”，不要只讲口号。

**非技术主题：**

- 每个关键概念配一个具体案例。
- 推导过程不要跳步。
- 练习可以是辨析题、论述题、场景分析或材料题。
- 标注必要来源。用户提供、许可允许或用户明确授权复用的资料，可以较长保留原文、原图、原表和原题；其他外部资料以改写、短引和结构复用为主。

### 5. 官方资料要嵌在知识点旁边

不要把官方文档和资源全部塞到课程末尾。讲到具体 API（应用程序接口）、概念、定理、工具命令时，如果有官方文档、标准、教材、论文或源码链接，就在旁边补一条短链接。链接位置、课程级来源和资源导出规则以 `courseware-format.md` 为准。

好写法：

> 深入看：React 官方文档的 [`useState`](https://react.dev/reference/react/useState) 页面适合查参数、返回值和常见用法；先学完本节再看，不要一开始就陷进 API 细节。

写法要求：

- 每个链接必须指向直接解释当前知识点的页面。不要堆资源列表。
- 一句话说明“为什么现在看这个链接有用”。
- 技术主题优先官方文档、标准、源码；非技术主题优先教材、论文、课程大纲或权威资料。

### 6. 用学习者已有经验做迁移

如果学习者画像里记录了已会语言、工具或领域经验，要主动利用，但不要硬套。

示例：

- 学过 Java 再学 Python 装饰器：可以先类比成“给函数包一层可复用处理”，再强调它不是 Java 注解，运行时机制不同。
- 有后端经验再学 React 状态：可以把状态理解成“组件自己的内存”，但要说明它不是服务器缓存，更新会触发渲染。
- 有数学基础再学机器学习：可以用函数、向量和优化来解释，但不要默认他懂工程实现。

规则：

- 类比只在能缩短理解路径时使用。
- 类比必须说明边界：哪里像，哪里不像。
- 薄弱前置只补当前章节需要的一小段，不要偏题变成另一门课。

### 7. 误解和坑点就地拆

真实常见误解要写，但不要凑数量，也不要固定做成“踩坑表”。它应该自然出现在相关知识点旁边。

可用写法：

- “这里容易误会的是……”
- “如果你看到……，先查……，别急着……”
- “这个问题只在……场景下会出现；平时不用提前焦虑。”
- “它和 XXX 不一样，关键区别是……”

没有真实来源、真实经验或清晰场景时，不要写“常见陷阱”。

### 8. 版本说明只在影响学习时写

技术主题只有在 API（应用程序接口）、语法、工具链或依赖有破坏性变化时才写版本说明。

非技术主题标注教材版次、论文年份或数据时间即可，不硬凑“版本变化”。

### 9. 面试题不要变成背答案

面试导向模式下，每章可以关联 1-3 道典型题，但必须让学习者先作答。题型和字段写法按 `courseware-format.md`；中文参考内容至少覆盖：

- 回答要点：应该覆盖哪些点。
- 追问方向：面试官可能继续问什么。
- 判断标准：什么回答算理解了，什么回答只是背词。

不要把面试题写成静态 Markdown 列表，也不要只给“标准答案”。

### 10. 术语、题库和闪卡的中文呈现

默认文件策略以 `courseware-format.md` 为准；本指南只规定中文正文该怎么呈现术语、题库和复习内容。

中文写法：

- 术语多时，在本章末尾写“术语速查”，但不要把正文变成术语表。
- 面试题、考试题和课后练习写进本章，用 `courseware-format.md` 规定的可保存练习块让学习者先答再看解析。
- 复习问题来自已学过的关键概念，由学习阶段写入 `concepts.json`，不要在课程生成阶段预制一堆没学过的闪卡。

### 11. 章节和小节收束要有信息量

小结不是把标题抄一遍。它应该帮学习者完成整理：

- 本章主问题是什么。
- 本章最重要的 3-6 个概念或判断标准是什么。
- 哪个例子最能代表本章方法。
- 下一章会接着解决什么缺口。

如果没有具体下一步，就不要写“建议下一步”。空泛的“完成练习后进入下一章”没有价值。

## 中文禁忌

- 不要英文直接机翻；用中文思维重写。
- 不要堆术语不解释。
- 学习者需要亲自运行的代码，不要只给代码而不给必要运行命令和预期输出。
- 不要把生成过程写成中文课件正文的一部分。
- 不要只讲是什么，不讲为什么和怎么选。
- 不要忽略影响学习结果的版本变化。
- 不要无差别堆官方文档原文；用户提供、许可允许或明确授权复用的材料可以保留长片段，其他外部资料在具体知识点旁边放短链接和必要短引即可。
- 具体 AI 写作警惕词、禁用句式、翻译腔规则见 `references/anti-ai-writing.md`。
- 不要为凑结构硬写“常见陷阱”“建议下一步”“面试题”。
- 不要写固定口号式标题，例如每节都来一句"先记住一句话"。

## 生成自检清单

每个小节正文写完后，执行 `anti-ai-writing.md` §7 自检流程。此自检不可替代 Phase 2 的阻塞学习者视角审查。
